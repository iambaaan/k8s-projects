## 🚀 Basic Usage

### Check the Kubernetes cluster

```bash
kubectl cluster-info
```

Check the available nodes:

```bash
kubectl get nodes
```

### Create resources

Apply a Kubernetes manifest:

```bash
kubectl apply -f deployment.yaml
```

Apply all manifests in a directory:

```bash
kubectl apply -f .
```

### Check resources

```bash
kubectl get pods
kubectl get deployments
kubectl get services
```

For a specific namespace:

```bash
kubectl get all -n <namespace>
```

### Inspect resources

```bash
kubectl describe pod <pod-name>
kubectl describe deployment <deployment-name>
kubectl describe service <service-name>
```

### Check logs

```bash
kubectl logs <pod-name>
```

For a multi-container Pod:

```bash
kubectl logs <pod-name> -c <container-name>
```

### Access a running container

```bash
kubectl exec -it <pod-name> -- /bin/bash
```

If Bash is not available:

```bash
kubectl exec -it <pod-name> -- /bin/sh
```

## 🔐 Secrets and ConfigMaps

Secrets are used to store sensitive configuration such as passwords and database credentials.

ConfigMaps are used for non-sensitive configuration.

Example:

```bash
kubectl get secrets
kubectl get configmaps
```

Inspect a Secret:

```bash
kubectl describe secret <secret-name>
```

## 🌐 Services

This repository contains examples of different Kubernetes service types.

### ClusterIP

Used for internal communication between workloads inside the cluster.

```bash
kubectl get svc
```

### NodePort

Used to expose an application through a port on a Kubernetes node.

```bash
kubectl get svc
```

Example:

```text
PORT(S)
80:30004/TCP
```

The application can then be accessed through:

```text
http://<node-ip>:30004
```

## 🔄 Deployments and Updates

Deployments are used to manage replicated applications and provide features such as rolling updates.

Check rollout status:

```bash
kubectl rollout status deployment/<deployment-name>
```

View rollout history:

```bash
kubectl rollout history deployment/<deployment-name>
```

Rollback:

```bash
kubectl rollout undo deployment/<deployment-name>
```

## 🐛 Troubleshooting

Useful commands when a workload is not working:

```bash
kubectl get pods
kubectl describe pod <pod-name>
kubectl logs <pod-name>
kubectl get events
```

For more detailed information:

```bash
kubectl get pod <pod-name> -o wide
```

Check the complete YAML generated by Kubernetes:

```bash
kubectl get pod <pod-name> -o yaml
```
